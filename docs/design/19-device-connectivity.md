# 设备身份与 LAN / Tailnet 共存

## 行为约定

设备以持久公钥生成的 `device_id` 识别。同一设备在目录和界面中显示一条记录，
LAN 与 Tailnet 是它的连接路径。首次连接及断线恢复按 LAN、Tailnet 的顺序尝试；
已经建立的健康连接保持当前路径。

设备在任一路径完成一次 xmesh 配对后，两条路径使用同一份设备信任。
设备的应用角色由 xmesh 本地信任记录授予；网络控制面决定其网络路径是否可达。
撤销 xmesh 信任终止该设备的全部路径与会话。

界面将本机信任记录中的 `tag:peer`、`tag:device` 等称为“配对权限组”。
目标设备使用自己授予调用方的权限组匹配 `agent.authz`。Tailscale / Headscale
设备页的“网络标签”来自控制面，仅参与网络策略；两者独立保存和管理。
版本 2 的连接、配对和角色启用支持普通用户设备，无需分配网络标签。
接入密钥的网络标签默认为空；管理员可按需手动填写。已有网络标签继续保留。
Funnel 公网入口仍需控制面允许 Funnel 与 HTTPS，具体授权对象由网络策略配置。
权限矩阵能评估网络策略；缺少目标设备本地配对记录时，v2 工具授权显示为未知。

升级使用配置及设备协议版本 2，结束旧版连接并重新配对。
升级前保存旧配置和信任文件；回滚使用原程序及原配置。旧 Tailnet 配置若仅声明 `tag:device` 的应用授权，迁移将该授权的原有工具与后端限制复制为版本 2 本机使用的 `tag:peer`；已经声明的 `tag:peer` 保持原样。

## 身份与配对

- 状态保存到 `identity-v2`。Ed25519 私钥、证书在一个原子记录中保存，权限为 0600。
- `device_id` 是 `dev-` 加完整的 SHA-256(SPKI) 十六进制摘要。
- 证书续期保留公钥，证书主体绑定设备 ID；显示名称、网络地址单独保存。
- 两种网络都使用 TLS 1.3/mTLS，验证相同的设备公钥和当前信任记录。
- 一次密码配对使用 SPAKE2，将双方版本 2 身份文档纳入确认 transcript。
- 配对引导使用独立 ALPN `xmesh-pair/2`，只能访问 `/mesh/v2/pair/`。
- 密码和信任分别维护版本；确认与版本检查在同一事务中完成，撤销后的旧确认失效。
- 同一设备的名称变化保留本地 alias；同名不同身份分配独立 alias。
- API、CLI 和运行时共用信任服务；离线写入取得文件锁、重新读取、原子替换。

## 网络与目录

配置版本 2 使用 `mesh.lan.enabled` 与 `mesh.tailnet.enabled` 两个开关。
默认开启 LAN，Tailnet 由用户启用。网络组件独立启动、重试与关闭。
某一路未就绪时，其余路径和本机管理仍可运行。

目录以设备 ID 为主键。mDNS、Tailnet 状态和手动地址仅提供候选；
候选经握手证明身份后才归入设备。手动配对地址作为设备的连接提示持久保存，重启或网络组件换代后重新探测；地址复用仍须核验原设备公钥。每条路径独立保存来源版本、验证时间、
健康状态和退避状态。单路发现过期只更新该路径。

每对设备最多两条链路，按拨号方向各占一个槽：本机拨出的是“出”槽，对端拨出的是“入”槽。两端各自拨自己的槽、各自提交，互不等待；较小设备 ID 的一端分配 epoch，两个方向的 epoch 全局递增。逻辑会话归开启它的一端的槽：本槽没有连接时借用另一槽的连接，本槽连上后新会话直接走本槽，借用中的旧会话安静（无未确认数据且 2 秒内无流量）后用 resume 迁回。第二条连接按需建立：本端有待开会话或近 5 分钟有流量的自开会话，而出槽为空时才拨；两条都空闲 5 分钟，较新的那条由拨出它的一端关闭，唯一的一条永不因空闲关闭。同槽内换路径（smart 复核或链路无响应）先拨新连接，提交后旧连接进入排空，会话迁完（至多 10 秒）再关。心跳连续约三拍无任何入站帧即判为可疑：会话先迁到健康连接，并立即拨替代连接，不等 30 秒死亡判定。hello 能力 `dual-slot-v1`：对端不带该能力时仍只保留一条连接，行为与旧版一致。
任一端可发起候选连接，只有完成 COMMIT 确认的链路才承载业务消息。
双方进程身份、链路代次和连接 ID 用于拒绝旧连接的迟到结果。

首次连接与恢复的 LAN 候选总预算为 2 秒，包含等待 LAN 发现；收到 Tailnet 连接候选时也给 LAN 相同的优先机会。Tailnet 拨号预算为 5 秒。
失败路径分别按 1、2、4、8、16、30 秒退避。活动链路每 5 秒发送一次心跳用于测量往返；
收到任何入站帧或心跳回应都算链路存活，连续 10 秒没有收到数据时面板显示“连接不稳定”（`unstable`），连续 30 秒没有收到任何数据才判定链路断开。
心跳在写路径之外等待回应，大于 192 KiB 的消息按连续的分片帧发送，使心跳回应不会排在多兆字节的写入之后。已有连接保持路径，恢复后也不触发额外回切。

同一设备公钥若对应多个经认证的运行实例，目录标记身份冲突，拒绝新连接并结束已有逻辑会话，等待实例冲突消除后建立新会话。

目录向每个订阅者广播最新版本。异步任务提交结果前检查设备身份、网络组件版本、
连接代次和信任版本。配置与 drain/resume 按单调版本顺序应用。

## 路径选择

每次探测的耗时和成败进入该设备该路径最近 5 分钟（最多 200 个样本）的窗口，得到延时中位数、p90、抖动（p90 减中位数）、丢包率和断流次数（成功后紧接着失败）；窗口随路径一起在提供者换代、设备撤销时清除，只失败过的路径也保留历史。这些指标经 `GET /v2/peers` 的 `paths[].quality` 给出，设备详情显示。

`mesh.path_selection` 决定用哪条路径。`manual` 严格按 `priority`（没列出的按 LAN、Tailnet、Cloudflare 排在后面），第一条能连上的胜出；`disabled` 的路径既不拨出也不接受。默认的 `smart` 按分数选：延时中位数 + 2×抖动 + 丢包率×2000 毫秒 + 每次断流 300 毫秒（上限 3000）+ 路径偏置（LAN −50、Cloudflare +30，只在接近时倾向少依赖第三方的路径），越低越好；跨国链路被随机阻断时延时看不出来，所以丢包和断流权重远大于延时。样本少于 5 个的路径不打分，排在健康的已打分路径之后并按 `priority` 排序；已被判为不健康（丢包 ≥30% 或断流 ≥3 次）的路径排在它们之后，所以没有数据时与手动模式一致；丢包为 100% 的路径排在一切有应答的路径之后。

已建立的连接在 smart 下由拨出该连接的一端每 5 秒复核（两端各自测的是同一条链路的两个方向，只让一端决定，避免来回拉扯）：另一条路径的分数比当前低四分之一以上且至少低 30 毫秒，并连续保持 30 秒，才换路径：先在同槽拨新路径，提交后再关旧连接；连接存活不到 60 秒不动。当前路径不健康（丢包率 ≥30% 或 5 分钟内断流 ≥3 次）而另一条路径健康且分数更低时不等 30 秒，存活满 10 秒即可换。逻辑会话在新连接上 resume 续传，写 `device_path_switch` 审计事件（新连接提交时才写）。接收端不再因为本端偏好 LAN 而把对端选的连接让给 LAN：双槽下对端拨的连接只占对端的槽。

配置变化时 `Rebalance` 生效：manual 下不在最优先可达路径上的连接被断开重连，停用路径上的连接在两种模式下都被断开。

## Cloudflare 路径

设备没有公网地址时，`cloudflare` 路径让每台设备用自己的 Cloudflare Tunnel 互连。每台可被连接的设备运行一条隧道，主机名各不相同，cloudflared 用 `tcp://127.0.0.1:7434` 规则把隧道转发到本机回环监听；隧道只出站，不需要入站端口。连接方先向对端主机名发起外层 WebSocket（携带 Access 服务令牌），再在其中完成与其他路径相同的固定公钥 mTLS 和 `/mesh/v2/link`。Access 只做门禁，设备身份、配对信任、标签和 `agent.authz` 与其他路径完全一致，不信任任何 Cloudflare 头。

该路径在默认顺序里排最后：前面的路径都拨不通时才在 15 秒预算内尝试（顺序可由 `mesh.path_selection` 改变）。隧道往返较慢，所以探测每 30 秒一次，探测超时 10 秒、有效期 60 秒。监听默认只放行已配对设备（握手阶段要求客户端证书），未配对设备只有在被连接端设置了连接密码期间（邀请新设备时由 `xmesh cloudflare invite` 打开，成功、失败或 15 分钟到期后关闭）才能经隧道配对，或显式设置 `allow_pairing`。只拨出的设备不设置 `hostname`，不监听。

已配对设备之间还能下发连接方式（`POST /mesh/v2/offer`，经已验证的路径、要求客户端证书属于已配对设备）：发送设备替对方创建隧道，把对方自己的隧道令牌、Access 服务令牌和两边的主机名交给对方。接收设备把它放进私有、有上限、会过期的收件箱，发送者取自连接证书而不是请求体；用户经控制接口确认后才写文件和配置，拒绝或过期则删除。发送设备拨不通对方时（对方只拨出到它），提议留在发送设备的待送达文件里，对方定期经自己的连接向它取（`POST /mesh/v2/offer/collect`，存入收件箱后再 `…/ack`），所以确认前不会丢，重复取只会覆盖同编号的提议。这不授予信任，也不含 Cloudflare API 令牌。同一通道还能下发 Tailscale 预授权 key（`tailnet` 提议）：发送设备用自己的管理连接生成、或由用户提供，接收设备确认后写入私有文件并启用 `mesh.tailnet`；管理凭据不出发送设备，key 的控制面标签与 xmesh 设备标签无关。

隧道可由 `xmesh cloudflare` 经 Cloudflare API 创建（`internal/cfadmin`）：每台设备一条远程配置的隧道、一条代理 CNAME、一个只放行网格服务令牌的 Access 应用，同网格设备共用一个服务令牌。API 令牌只存在运行命令的机器的系统钥匙串或 0600 文件里，内核不持有，内核只收到隧道令牌文件的路径。配置了 `tunnel_token_file` 时内核自己运行 `cloudflared tunnel --no-autoupdate --protocol http2 run --token-file …`（HTTP/2 写死，令牌不出现在进程参数里），退出后按 1 秒起翻倍到 1 分钟的间隔重启；cloudflared 的输出被丢弃，因为它会回显连接器信息。

## 直连路径

`direct` 路径让设备在自己的公网地址（`mesh.direct.listen`，默认 `0.0.0.0:7435`）上监听，对端按 `mesh.direct.peers` 或配对时填写的地址直接拨入，不经第三方，默认关闭。它与其他路径一样走固定公钥 mTLS 和 `/mesh/v2/link`；监听端口默认只放行已配对设备（握手要求客户端证书），未配对设备只在被连接端设置了连接密码期间（邀请）或显式 `allow_pairing` 时才能到达配对。路径偏置 −10，探测每 15 秒一次。

公网端口在认证前由 `connectivity/guard.go` 加固：

- 来源白名单：`allow_ips` 非空时，不在名单内的来源在 TLS 之前即被关闭。
- 预认证并发上限：尚未完成握手并发出请求的连接总数不超过 `max_preauth`（默认 64），单个来源最多 8 条；TLS 握手与读请求头各有 10 秒期限（`ReadHeaderTimeout`）。
- 按来源退避：连接没发出请求就关闭（握手失败、慢速占用）算一次失败，该来源在 1、2、4…秒（上限 1 分钟）内的新连接被直接关闭；发出一次请求即清零。10 分钟没有活动的来源记录被丢弃。

这些限制只作用于直连监听，不影响 LAN、Tailnet 与 Cloudflare；已认证后的连接不受预认证限额占用。

## 逻辑会话

内部节点通信使用 `/mesh/v2/link`，子协议为 `xmesh-link-v2`。
同一设备链路承载多个隔离的 MCP 逻辑会话，恢复时保留 MCP 实例。
调用方身份为 `device_id/logical_session_id`，路径变化保持资源归属。

双向消息使用会话 ID、顺序号、确认号和链路代次。接收方记录消息并入队后确认，
重复消息不会再次交给 MCP。恢复补发未确认帧，覆盖请求、响应、取消、进度和反向调用。
每会话的恢复凭据只保存在内存中，并绑定双方设备身份、进程身份和 OAuth 客户端。

单帧上限为 16 MiB，每会话缓存上限为 32 MiB，进程总上限为 128 MiB。
缓存满时施加背压，控制消息保留额度。物理路径断线后的恢复窗口为 120 秒。

恢复保留 PTY 的 PID、owner 和 cursor、已接受的 exec 任务及结果、per-caller 后端，
以及仍在 TTL 内的租约。请求超时、显式取消和租约到期继续生效。
用户关闭、撤销设备信任、恢复窗口到期或服务退出时执行一次完整清理。正常退出先在 500 毫秒的总预算内通知对端结束逻辑会话，再关闭网络组件；网络中断保留恢复窗口。恢复期限独立于在途拨号，到期后的握手结果不能复活旧会话。
远端进程身份变化结束旧会话；结果不确定的写入或执行不会自动作为新操作再次执行。

## 并发约束与回归

| 交错事件 | 处理规则 | 回归位置 |
| --- | --- | --- |
| LAN / Tailnet 同时发现、同一地址换设备 | 按已验证公钥合并；探测任务包含设备 ID；连接提示不授予信任 | `device/directory_test.go`、`connectivity/node_test.go`、`device/hints_test.go` |
| Tailnet 先出现、LAN 稍晚发现 | 首次拨号和入站仲裁共享 LAN 的有限发现机会 | `devicelink/manager_test.go` |
| 双向同时拨号、多逻辑会话一起重连 | 每端各提交自己的槽；同槽新连接提交后旧连接排空；旧 epoch 不承载消息；一槽断开另一槽继续承载；借用与迁回；无响应连接提前替换 | `devicelink/manager_test.go`、`devicelink/slots_test.go` |
| 公网直连端口被扫描、慢速占用握手或猜测配对 | 白名单、预认证并发上限与按来源失败退避，均在认证前生效 | `connectivity/guard_test.go` |
| provider 关闭、失败重试、旧握手或旧发现迟到 | 关闭时立即撤销旧 provider 代次，提交时再次校验；其余网络独立运行 | `connectivity/node_test.go`、`device/directory_test.go` |
| 配对确认与密码轮换、设备撤销交错 | 同一事务内验证密码版本与设备信任版本；确认回执绑定当前信任 | `device/pairing_concurrency_test.go` |
| 同一公钥对应多个进程 | 发现、拨号、激活与业务接收均检查冲突；结束原会话 | `device/directory_test.go`、`devicelink/manager_test.go` |
| 探测失败与较新成功交错、旧进程地址失效 | 失败按探测开始时间撤销路径证据；迟到失败与旧探测结果不能覆盖较新成功，已失效旧实例证据退出身份冲突判断 | `device/directory_test.go`、`connectivity/node.go` |
| 旧拨号失败、旧 sys.info 回读覆盖新连接 | 仅当前设备与连接代次能发布结果；路径退避分别保存 | `role/gateway/coexist_race_test.go` |
| 断线路径恢复、ACK 丢失、业务重发 | 双向序列与确认去重，恢复已有 MCP 会话；健康路径保持 | `devicelink/session_test.go`、`devicelink/manager_test.go` |
| 恢复期限到达时仍有拨号在途 | 独立执行期限清理，拒绝迟到的激活结果 | `devicelink/manager_test.go` |
| drain/resume、热配置与停机交错 | 管理动作按代次串行；停机等待工作协程退出；资源归属保持设备逻辑会话 | `app/control_test.go`、`connectivity/resources_test.go` |

连接、恢复、离线、设备信任撤销与身份冲突写入 `device_link_*` 审计事件。记录包含设备 ID、路径类型和拨出方向（工具名形如 `device.link.lan.out`，`out` 是本机拨出，`in` 是对端拨出），可与逻辑会话的工具审计关联。

## 接口与验收

控制 API、Schema、Go/TypeScript 类型、CLI 和 UI 统一升级到 v2。
设备返回设备 ID、alias、信任、路径集合、活动路径和连接状态；
设备列表与拓扑使用设备 ID 合并显示。远程排空通过运行节点的本机控制通道转发，使用已验证设备路径和 xmesh `tag:admin` 授权，按设备 ID 定位目标并逐台报告结果。外部 MCP 客户端继续使用 `/mcp` 的 PAT/OAuth。

## 运行期生命周期与应用结果

Funnel 入口和 Tailnet Gateway 监听器使用持续的接收队列，等待路径就绪，并在提供者重建后重新绑定。Funnel 后台启用失败会进入节点警告和配置应用结果，并在监听成功后清除。网络配置重载等待当前路径配置就绪；无法启动的 LAN/Tailnet 路径分别通过 `apply_errors` 的 `mesh.lan`、`mesh.tailnet` 返回，仍在初始化的路径也会在等待截止后返回待应用状态。

入口对同进程 Agent 的调用使用 `tag:ingress` 授权，沿用 OAuth 调用方身份。设备证书在运行期间每小时检查，到期前 30 天使用同一公钥续期；已创建的服务端和客户端 TLS 配置在每次握手时读取当前证书。

逻辑会话在断网期间关闭后保留其已认证的关闭通知，直到对端确认或恢复窗口到期。关闭通知会触发重连并跨承载连接重放，使对端 MCP 会话和调用方资源随之释放。

## 入口委托与控制接口升级

远端逻辑会话携带 OAuth client 时，接收设备验证本地保存的对端信任含 `tag:ingress`，并且只使用 `tag:ingress` 的 Agent 授权。设备同时具备的 peer/admin 角色不并入该委托会话；会话恢复继续校验同一个 OAuth client、会话 token 和信任代数。普通设备会话及同进程入口调用沿用各自身份边界。

设备信任导入支持本机明确选定的 `tag:admin`，用于受认证的远程排空；远程管理处理器在 Gateway/Ingress 单角色节点也可用。每设备超时覆盖完整的排空响应等待，连接建立和 TLS 握手保留独立限时。

远程排空将路由别名解析为持久设备 ID，并同步设置托管 CI runner 的排空状态。CLI 的版本 2 请求可由调用方取消，各设备获得完整的请求期限，排队等待并发名额的设备在开始请求时计算超时。

桌面升级在停止内核前保存控制状态提供的实际配置和状态目录。升级后的进程按该记录迁移；旧更新流程没有记录时，macOS 与 Windows 使用 `xmesh migrate --name xmesh-<node>` 读取 LaunchAgent、用户登录任务或 SCM 服务定义中的配置参数。显式路径迁移继续使用 `--config` 和 `--state-dir`。迁移配置中的 YAML 授权别名时保留对应映射的授权限制。

本次 v2 升级采用内核、CLI 和 UI 协调更新，备份配置和旧状态后迁移并重新配对。`/v1` 的证书配对语义无法映射为 v2 的设备信任授权；升级后的旧客户端读取版本信息并进入版本不匹配状态，回滚使用原二进制和对应备份。
