# 远程终端与文件传输

在「运行」中增加远程终端和文件传输。两个页面共用工具调试台的主进程 MCP 会话、现有 Gateway PAT、权限、配额和来源审计。

## 远程终端

选择设备并打开终端，可指定 shell、cwd、名称和环境变量。xterm 渲染 ANSI 与光标，输入按约 24ms 合并串行写入，终端尺寸变化在 150ms 后同步。输出通过带 cursor 的 25 秒 long-poll 增量读取。服务端缓冲被覆盖时显示提示，断线后保留 cursor 重试并刷新会话列表。

`pty.list` 顶层增加来自已认证连接的 `caller_id`，便于客户端比较 owner 并接管孤儿会话。其他 owner 的会话显示只读；主动移交需填写接收方 caller ID，孤儿接管由服务端验证同节点身份和原有 OAuth 约束。INT、TERM、KILL 与关闭均显示目标确认。关闭后继续读取保留输出。

xterm 的运行时主题和尺寸样式使用每次 HTML 响应随机生成的 CSP nonce。渲染页面、响应头和终端样式共享本次 nonce，脚本策略继续只允许本地脚本。样式元素工厂在终端同步初始化期间覆盖并立即恢复，其余终端样式经 documentOverride 设置 nonce。Electron 测试检查所有终端 style 的 nonce 及控制台错误。

## 文件传输

主进程原生文件对话框发出上传文件的随机 ticket；渲染进程只获取 ticket、文件名和大小。下载目标也由原生保存对话框确定。传输正文、Base64 编解码、哈希与磁盘写入在主进程完成，页面显示阶段、累计字节、哈希和错误。

根据目标工具 inputSchema 中的 transfer_id 和 byte_offset 探测分块能力。支持分块的节点按 1 MiB 顺序发送或接收，不在客户端固定整文件上限，遵守节点配置。较早节点使用单次传输，超过 10 MiB 时提示升级。

上传先计算整文件 SHA-256，再按块发送，同步复核源文件信息。默认 force:false，存在冲突后通过原生覆盖确认重试。下载先验证普通文件元数据，每块检查编码、大小和 SHA-256，末块检查累计大小与整文件哈希；写入目标目录内的临时文件，fsync 后再次检查本地目标是否变化，再原子安装。校验失败与取消清理本地临时文件，既有本地文件保持原样。

每个面板同时传输一个文件，可取消进行中的调用。远端未完成分块会话由节点超时回收；取消提示说明需要检查远端状态。传输元数据保留最近 20 条，上传 ticket 最多保留 8 个，切换内核或断开连接会清理面板上下文。

## 依赖与验证

本页基于工具调试台 PR #96。文件操作需要目标节点提供 fs.upload/fs.download，分块能力由文件传输 PR #95 提供。能力缺失时显示对应提示。

已在 macOS 上验证 Electron 的终端键盘输入、resize、信号、只读展示、孤儿接管、关闭，以及二进制文件往返、冲突确认、响应完整性和凭据隔离。单元测试覆盖空文件、分块往返、哈希错误、取消清理、保留本地旧文件和旧版大小限制。

另以文件传输依赖提交 `55d2e4c0ca9b8416ecee90b7acbdc82612f7640d` 的 Go 文件 overlay 构建真实内核，完成回环 Gateway + 面板生产服务联调：sys.info、exec.run、PTY 的 open/write/read/resize/transfer/非 owner 写入拒绝/signal/close，以及 12,583,003 字节上传下载哈希一致和 panel 来源审计。此验证使用本机回环；实际多设备网络和 Windows/Linux 原生交互仍需对应环境验收。
