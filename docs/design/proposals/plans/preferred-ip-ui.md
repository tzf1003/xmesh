## 1. 用户能做什么(对应界面)

| 需求 | 界面位置 | 内核需要什么 |
| --- | --- | --- |
| 在哪里开启优选 IP | 接入与轮换 · 顶部总开关 | `preferred_ip.enabled`,关闭时所有连接走 DNS,池与设置保留 |
| 连接用哪个 / 哪些 IP | 接入与轮换 · 默认接入方式:智能选择、固定指定 IP(可多选) | `mode: smart / fixed`,`fixed_ips` |
| 每台设备单独设置 | 接入与轮换 · 按设备覆盖表(跟随默认 / 智能 / 固定 IP / 不用优选) | `peers: {设备ID: {mode, ips}}`,拨号时按对端取策略 |
| IP 轮换与故障切换 | 接入与轮换 · 右侧(顺序、单个 IP 超时、阶段预算、连续失败摘除与冷却、全败回退 DNS、丢包时迁移) | 池管理器维护每个 IP 的失败计数与冷却;拨号按顺序逐个完整尝试(#152 已有) |
| IP 池怎么构建 | IP 池与来源 · 池概览与构建规则(只收 Cloudflare 段、跨来源去重、上限 64、手动条目不淘汰) | 池管理器统一汇总、校验、去重、限量 |
| 池的来源设置 | IP 池与来源 · 来源列表(手动、本地文件、订阅地址、自动测速),每个可独立开关 | `sources: [{type, enabled, ...}]` |
| 定时优选 / 定时刷新订阅 | IP 池与来源 · 定时更新;总览 · 定时自动优选 | 调度器:测速间隔、订阅刷新间隔、空闲时才跑 |
| 查看结果 / 手动测速 / 导入 | 总览(候选表、立即测速)、测速中卡片、导入弹窗 | 控制接口:状态、扫描(带进度)、导入预检 |

## 2. 池与选择的行为定义

1. 汇总:各来源开着的条目合并,先出现的在前。
2. 校验:必须在 Cloudflare 公布的 IP 段内;订阅或文件里有段外地址,整份来源拒绝并在界面提示。
3. 去重、限量:跨来源去重,总数最多 64;超限时先淘汰评分最低的自动来源条目;手动条目只能手动删。
4. 评分:对对端真实隧道主机名做 TLS 握手(带证书校验),按延时与丢包打分;入池前先测一次,失败的不入池。
5. 选择:`smart` 按评分从高到低;`fixed` 只用勾选的。(按池轮换已确认先不做。)
6. 拨号:按顺序逐个完整尝试(TCP、TLS、Access、WebSocket、内层握手),单个 IP 4 秒;优选阶段总预算为拨号时限的 60%;连续失败 3 次摘除并冷却 30 分钟;全败才回退 DNS(可关)。
7. 已建立的连接:默认不动;可选"当前 IP 丢包超过 30% 时迁到更好的 IP"(会话自动续传)。

## 3. 配置形态(草案)

```yaml
mesh:
  cloudflare:
    preferred_ip:
      enabled: true
      mode: smart            # smart | fixed
      fixed_ips: []
      attempt_timeout: 4s
      fail_threshold: 3
      cooldown: 30m
      fallback_dns: true
      migrate_on_loss: true
      sources:
        - {type: manual, ips: [104.19.205.88]}
        - {type: file, path: /abs/preferred-ips.txt}
        - {type: url, url: https://example.com/cf-best-ip.txt, refresh: 12h}
        - {type: scan, interval: 6h, sample: 200, keep: 8, ipv6: false, idle_only: true}
      peers:
        dev-xxxx: {mode: fixed, ips: [172.64.153.21]}
        dev-yyyy: {mode: off}
```

现有 `preferred_ips` 和 `preferred_ips_file` 保持兼容,等价于一个 manual 来源和一个 file 来源。

## 4. 内核工作

- 新包 `internal/cfpreferred` 增加池管理器:来源汇总、校验、评分状态、失败计数与冷却,状态落盘(重启后保留)。
- 调度器:测速、订阅刷新,可配置间隔,设备空闲时才跑,结果写回池。
- 订阅拉取:只允许 https、限制大小和超时、内容校验后才入池,默认不开。
- `dialCloudflare` 改为向管理器要"对这个对端的有序 IP 列表",并回报成功与失败。
- 配置校验与 schema、`NeedsRestart` 白名单(热生效,不需要重启)。
- 控制接口:读取状态(池、评分、当前使用、下次运行时间)、保存配置、触发扫描并推送进度、导入预检。
