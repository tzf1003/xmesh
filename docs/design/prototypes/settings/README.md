# xmesh 导航与设置完整方案

本方案以当前设备、会话、CI 与 Tailnet 设计预览为基础，统一顶部角色控制、侧栏信息架构和设置归属。配套预览为 `settings/index.html`；可从任意预览页切换各模块。

## 1. 整体结构

顶部固定显示本机名称、功能搜索、Agent / Gateway / Ingress 角色按钮和应用状态。三个角色共用相同的菜单与设置面板交互，在当前页面内完成启停或配置。

侧栏：

- 网络：网络拓扑、设备、会话。
- 安全与接入：访问与授权、公网入口。
- 独立模块入口：CI 运行器、Tailscale 管理。
- 运行（折叠菜单）：接入控制、远程终端、文件传输、工具调试台、桌面控制。
- 底部：设置。

「会话」包含实时执行、历史记录与审计、持续会话和资源。CI 与 Tailnet 分别拥有自己的完整页面及模块设置。

原「高级」导航组移除。原配置入口中的业务字段按下面的映射迁入所属模块；原关于更新入口迁入设置。历史页面标识保留重定向，以兼容搜索、托盘、通知与旧链接。

## 2. 顶部角色菜单

点击按钮只展开菜单。菜单顶部显示角色名称、运行状态和一句职责说明，下面提供「开启 / 关闭」和「角色设置」。点击设置打开右侧面板，保留用户当前页面上下文。

| 角色 | 职责 | 设置内容 |
| --- | --- | --- |
| Agent | 本机工具执行 | 默认工作目录、允许目录、保护目录、命令与 PTY 限制；关联工具授权、后端工具与沙箱配置 |
| Gateway | 客户端接入与路由 | 监听地址、接入协议、客户端认证、工具路由；链接令牌管理和接入控制 |
| Ingress | 公网接入 | 隧道 / HTTPS / Funnel、域名、TLS 证书、OAuth Issuer 与客户端访问策略 |

角色状态区分：运行中、已关闭、启动中、正在停止、需要配置、异常、配置已保存但待重启。图标、文案和颜色共同表达状态。提交期间禁用重复操作；失败时保留原状态并提供错误与重试入口。

开启 Ingress 前先检查必需地址、证书及网络依赖，配置不足时定位具体字段。关闭 Agent 时展示现有执行和会话的影响，默认等待任务完成；关闭 Gateway / Ingress 时说明相关客户端连接的影响。至少保留一个角色的现有内核约束继续生效。只读用户可查看设置，写操作按 capability 禁用。

配置保存和角色启停是独立动作。保存使用模块范围的差异预览，展示当前值、目标值和是否需要重启。应用后以实时内核状态回读，不能把配置写入成功当作服务已启动。

键盘支持：按钮可用 Enter / Space，菜单可用方向键与 Escape，关闭后焦点返回触发按钮。窄窗口始终保留三个角色入口，可缩短周边信息。

## 3. 配置归属

| 原有设置 | 新入口 | 边界 |
| --- | --- | --- |
| 本机名称、LAN / Tailnet / 共存 / 离线 | 设备 → 本机设备设置 | 只改变当前节点的名称与联网方式 |
| Tailscale 管理凭据、设备标签、网络策略、DERP | Tailscale 管理 | 区分控制面管理凭据与节点接入凭据 |
| 默认工作目录、允许与保护目录、执行限制 | 顶部 Agent → 设置 | 保留目录校验、权限收敛和相关风险提示 |
| 工具权限、客户端令牌与授权 | 访问与授权；角色面板提供上下文链接 | 角色设置不重复创建同一份权限配置 |
| Gateway 监听、接入与路由 | 顶部 Gateway → 设置 / 接入控制 | 接单排空和客户端连接状态仍在运行视图 |
| 公网域名、TLS、OAuth、监听方式 | 顶部 Ingress → 设置 / 公网入口 | 保留公网暴露确认及凭据只写边界 |
| 单文件大小、分块、校验、传输目录 | 文件传输 → 传输设置 | 使用 Agent 授权目录与文件策略 |
| 后端 MCP 注册、工具发现与调试 | 工具调试台 → 后端设置；Agent 设置关联 | 使用既有后端能力与策略 |
| CI 仓库、账号、并发、运行器托管 | CI 运行器 | 绑定与实例生命周期独立管理 |
| 审计保留期、记录读取与导出 | 会话 → 历史记录 → 记录设置 | 保留元数据与敏感正文边界 |
| 外观、语言、字体、登录启动、窗口行为 | 设置 → 通用 | 只影响本机应用偏好 |
| 日志、数据位置、诊断与恢复 | 设置 → 存储与诊断 | 提供安全诊断摘要，异常配置按模块定位 |
| 应用版本、检查更新、更新偏好、许可 | 设置 → 关于与更新 | 更新前保留现有任务影响确认 |

底层配置仍使用现有配置文件和控制接口。每个表单只更新所属字段，保留 YAML 注释、未知字段和其他模块的数据；ETag 冲突时保留草稿，要求基于新版本重新预览。跨模块依赖使用说明与跳转，不复制字段或建立相互独立的数据源。

## 4. 设置页 UI

采用「页内分类导航 + 设置分组」布局。

- 通用：外观三选一、语言、界面字体、代码字体、登录启动、关闭窗口后的行为。
- 存储与诊断：本机身份、数据和日志位置、诊断摘要、模块配置检查。
- 关于与更新：应用版本、检查更新、自动更新检查、预发布偏好、许可信息。

每个设置行包含标题、必要说明和右侧控件。应用偏好即时保存；业务配置在所属模块预览确认。低频维护功能放在通用和诊断页底部的折叠「维护工具」中。

当前预览包含角色启停菜单、Agent / Gateway / Ingress 设置面板、本机设备设置、通用设置、更新状态演示、诊断摘要和首次设置流程。其他模块的完整配置迁移属于正式实现范围。

## 5. 首次运行向导

只对尚未初始化的新用户配置执行首次启动检测。已有节点或已完成初始化的用户直接进入常规页面；版本升级不重新触发向导。

建议分开保存 `first_run_seen`、`setup_completed` 和恢复进度：首次展示后记为已看过，完成则标记完成；用户跳过或关闭后，下次启动直接进入工作界面。进行中的初始化任务保留恢复记录，通过设置中的维护工具继续，具体失败仍在相关模块中提示。

手动入口为「设置 → 通用 / 存储与诊断 → 维护工具 → 重新运行设置向导」，使用低强调文字按钮。手动重跑先读取现有配置，不清空节点、凭据或配对关系，最终显示本次差异。

预览顶部的「体验首次启动」用于设计评审。带 `?first-run=1` 打开设置预览可模拟一次自动出现；当前浏览器会话记录已展示状态。

## 6. CI 与 Tailnet 页面

CI：仓库与实例为主页面，展示当前任务和最近结果；账号及运行环境分开管理。绑定提供账号、注册令牌和接管已有运行器三种方式，保留公开仓库确认、账号占用检查及任务排空。

Tailnet：设备与标签、访问策略、权限矩阵、DERP 中继。策略与中继共用草稿，预览完整变更后应用，保存应用前快照。接入设备、凭据、标签和准入同步使用侧边面板。保留只读、未连接与控制面能力差异。

## 7. 落地顺序与验收

1. 统一导航与旧路由重定向，建立底部设置和首次启动状态。
2. 提取现有配置字段到 Agent / Gateway / Ingress 与设备模块，复用配置校验、预览、ETag 与生效流程。
3. 接入角色菜单的真实状态、排空、重启、错误和权限处理。
4. 接入 CI、Tailnet 和统一会话页的数据，逐项迁移低频配置。
5. 验收正常、只读、断连、无效配置、保存冲突、有运行任务和首次启动的场景；检查深浅色、键盘操作和窄窗口布局。

## 8. 当前交付范围

这套文件为可点击设计预览，业务操作使用示例数据，不改变真实设备、账号凭据、服务状态或控制面。设置字段的演示值与首次展示状态仅保存在预览页面或浏览器会话中。外观和窗口行为等新增偏好需确认并接入桌面应用设置层。

依据当前源码：`app.tsx`、`role-switches.tsx`、`Settings.tsx`、`Config.tsx`、`Configuration.tsx`、`Runtime.tsx`、`About.tsx`、`lib/settings.ts`，以及 CI / Mesh 的现有页面与契约。
