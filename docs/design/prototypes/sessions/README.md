# 会话 · 统一执行视图

打开 `index.html` 查看交互预览。页面统一展示工具调用、历史记录、审计事件以及持续会话与资源占用。

## 页面结构

- **实时执行**：命令、文件、PTY、桌面、UI 自动化及后端工具；展示设备、调用者、状态、耗时与执行对象。
- **历史记录**：已完成的执行与审计事件；支持类型、状态、设备、调用者、时间和事件筛选，并可加载更多记录。
- **会话与资源**：持续终端、桌面会话、UI 会话和后端租约，可查看关联执行历史。
- **详情**：调用身份、目标、生命周期、参数摘要、错误和原始审计元数据。
- **导航**：「运行」采用可折叠菜单，支持点击、Enter、空格及搜索定位；CI、Tailnet 与设置有独立入口，角色管理位于顶部。历史审计通过「会话 → 历史记录」访问。

窄窗口以侧边面板展示详情。顶部可切换示例与空状态、三种配色，并通过「演示完成 → 归档」体验运行条目进入历史记录的过程。

## 示例行为

所有设备、调用、时间、编号和身份均用于设计预览。实时示例更新已运行时长，完成演示会更新计数并将同一执行编号移动到历史列表。UI 异步任务在调用返回后继续显示为运行中，后台结果确认完成后归档。持续会话和租约分别保留自己的生命周期。

## 实现依据与接入范围

现有 `/v2/sessions` 提供 PTY、exec 和后端租约元数据，`/v2/audit` 提供按时间倒序的完成记录、系统事件及游标分页。桌面会话和 UI 异步结果有各自的查询入口。现有源码见：

- `ui/src/renderer/pages/Sessions.tsx`
- `ui/src/renderer/pages/Audit.tsx`
- `ui/src/renderer/lib/audit.ts`
- `docs/contracts/schemas/control-sessions.schema.json`
- `docs/contracts/schemas/audit-event.schema.json`
- `internal/audit/audit.go`
- `packages/ui-mcp/src/server.ts`

全工具实时列表、执行编号与完整生命周期属于本方案的接入需求，需在 Gateway / Agent 工具调用入口统一记录开始、排队、进度和结束，并适配 UI 后台任务、桌面动作及分块传输的实际生命周期。历史接口当前未提供通用调用关联 ID，正式接入应补充稳定的调用 / 执行标识以及来源层信息，以关联并区分 Gateway 与 Agent 的记录。

调用者和来源按接口声明呈现；来源未声明时保留未知状态。UI 任务的成功受理与任务最终完成分别显示。执行对象和参数摘要沿用审计契约，保留敏感正文的现有限制。

正式接入还应覆盖能力不可用、审计未启用、读取失败、刷新中断、分页边界、保留期及权限过滤；统计需注明作用域和时间范围，不能将当前分页数量当作完整历史总量。
