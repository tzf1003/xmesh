## NTFS 变更日志补读与持久游标

内部 `beginWorkspaceChangeTracking` 在初始授权完整、尚无执行或新增对象、外部 writer 自快照起已协调的条件下，重新核对工作树并刷盘现有 NTFS USN 日志 ID/起始游标。读取源使用保留卷根的 GUID，重开 GUID 根核对完整身份；仅打开可读取的既有日志。该路径不创建或调整系统 USN 日志，不启用 token 特权。

`checkpointWorkspaceChanges` 有界补读全部 reason，支持 V2 的 NTFS 文件引用和 V3 的完整 ID，验证记录长度、版本、字段边界、严格 USN 顺序和返回游标。读取前后核对日志 ID、FirstUsn、LowestValidUsn 和 NextUsn；重建、截断、回退、未知格式或无进度均保留错误。已知目录移出根后仍作为继承源，后续创建身份继续累计；每批新增 ID 核实并刷盘后才写游标。两帧之间强退会重读旧游标并按已记录 ID 去重。每次最多 65536 条事件、累计最多 10000 个身份，恢复协调器收到独立复制的游标。

已启用追踪的实时清理和恢复在 ACL 修改前先补读到调用时水位，再合并全部持久身份与当前树；若扫描仍发现未被流覆盖的对象，保留历史不完整错误。目录扫描 checkpoint 同样先消费流。进程退出回执与外部 writer 协调要求持续有效。删除、硬链接/reparse 变更和未知对象导入需要后续完整证明，当前保留义务；删除回执、导入子树证明、后台周期 checkpoint、生产协调器和 exec/ConPTY 接入继续实现，生产 Windows L2 保持 `sandbox.unavailable`。普通账号及卷不提供完整可读 USN 流时，该内部准入返回错误。
