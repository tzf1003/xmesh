# Windows 原生验收记录

日期：2026-10-15。代码基线：`8933cac`。

## 环境

GitHub Actions `windows-latest`，Windows Server 2025 Datacenter，版本 `10.0.26100`。Runner 镜像为 `windows-2025-vs2026`，版本 `20261007.264.1`。

证据：[PR 工作流 38748919084](https://github.com/tzf1003/xmesh/actions/runs/38748919084)，Windows job `116469821644`。该工作流整体失败，以下逐项记录实际执行结果。

## 结果

| 场景 | 结果 |
| --- | --- |
| exec 准入 | 挂起期间未执行用户代码，加入 Job 后恢复执行；通过 |
| exec 生命周期 | 主进程正常退出与超时均清理后代，继承的阻塞 stdin 管道释放；通过 |
| PowerShell 7 | 策略过滤环境下，标准启动与 Job 启动均通过 |
| Windows PowerShell 5.1 | 标准启动与 Job 启动均超时；仍需修复 |
| ConPTY 交互 | 使用生产环境过滤器，窗口调整为 `101×37`、Ctrl-C 中断后继续执行命令；通过 |
| ConPTY 生命周期 | TERM、KILL、shell 自行退出均清理后台进程；退出输出排空、重复关闭及启动失败清理通过 |
| 文件 | `internal/fs` 的 race 测试通过，包含共享读取时替换、锁定目标保留与临时文件清理、长路径读取和替换 |
| HTTP MCP | `Test_Gate1_MCPRealHTTP` 在 Windows PowerShell 命令处超时；仍需修复 |
| 静态检查与构建 | Windows `go vet ./...` 与 `go build ./cmd/xmesh` 通过 |

原生 exec 与 ConPTY 用例通过 `XMESH_TEST_WINDOWS_EXEC=1`、`XMESH_TEST_WINDOWS_PTY=1` 启用；全量测试使用 `go test -race ./... -timeout=120s`。文件用例在全量测试中执行。

## 后续验收

Windows PowerShell 5.1 的模块环境启动回归继续在 CI 执行。用户登录任务的登录触发、目标用户会话和 SCM 安装需在相应会话验收。Windows L2 当前拒绝启动，沙箱实现另行推进。

本次运行环境为 Server 2025；其他 Windows 版本的原生兼容性仍需对应环境验证。
