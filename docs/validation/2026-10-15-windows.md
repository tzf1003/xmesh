## AppContainer 隔离原语

`internal/winbox` 创建随机独立 profile，为进程设置空 capability 集合的 AppContainer 属性，并在进程结束后删除 profile。用例将测试二进制放入 profile 的私有目录，检查该目录中的写入、外部文件读写拒绝、父进程内存读取拒绝、可达环回服务的 Windows 访问拒绝、token 身份及 capability 数量；最后读回 profile 目录删除结果。Windows amd64/arm64 vet 和 amd64 测试交叉编译通过，原生结果待 CI。

该原语尚未接入工具执行路径。Windows L2 仍拒绝启动；真实工作目录授权、exec 与 ConPTY、子进程树和异常退出回收还需实现及验收。AppContainer 机制参考 [Microsoft 启动说明](https://learn.microsoft.com/en-us/windows/win32/secauthz/implementing-an-appcontainer)。

## 用户任务账户权限边界

`692e56e` 的 [PR 工作流 38765472473](https://github.com/tzf1003/xmesh/actions/runs/38765472473) 和 [push 工作流 38765466886](https://github.com/tzf1003/xmesh/actions/runs/38765466886) 中，三平台全量 race、vet 与构建通过。用户任务已通过 UTF-16LE 注册并运行，SID、Session 2、工作目录与复杂参数均匹配；Runner 是 SID 以 RID 500 结尾的内置 Administrator，实际 token 为提升状态，因原验收要求非提升而失败。

Microsoft 的 [RunLevel 说明](https://learn.microsoft.com/en-us/windows/win32/taskschd/taskschedulerschema-runlevel-principaltype-element)规定内置 Administrator 或关闭 UAC 时忽略该属性。验收改为同时读取父进程和任务的 TokenElevationType：有分离 token 时要求任务采用 Limited、非提升 token；无分离 token 时核对实际账户提升状态并记录边界。修订用例的原生结果待 CI；标准账户或启用 UAC 的普通管理员账户的非提升运行仍待对应环境验收。

## AppContainer 启动环境复验

`692e56e` 的上述两个工作流在 `CreateProcess` 阶段返回 Windows 错误 203（`ERROR_ENVVAR_NOT_FOUND`），隔离 helper 尚未运行。启动环境原语改为从当前 token 的 Windows Known Folder 获取 `LOCALAPPDATA`，与过滤后的调用方环境组合、排序后传给 Windows；覆盖缺失、重复和错误的同名值，且保持父进程其他环境变量不被继承。新增 helper 检查父进程秘密哨兵未继承。Windows amd64/arm64 vet 与 amd64 测试交叉编译通过，修订后的实际启动和隔离结果待原生 CI。
