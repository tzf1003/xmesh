本机批量执行满足 `直接执行 P95 × 1.25 + 250 ms` 的门限。工具调用与字节数统计包含每组一次预热。该基准采用本机 stdio，分布式联调使用回环 HTTP；实际部署的 tailnet、DERP 延迟与业务环境负载需要在相应节点复测。

测试结果区分 `fixtures: real/mock` 和 `coverage`。Electron 支持依赖 inspect 开启且实现后台测试契约的测试构建。脚本模式属于可信节点上的代码执行能力；Worker 和后台窗口管理用于故障隔离与资源回收。


## PR #100 审查修复复验

复验基线：`b59241b`。以下结果针对本次修复；上文完整交付、性能和桌面面板记录保留为原基线记录。

| 审查项 | 处理与证据 |
| --- | --- |
| Worker 异常退出缺少未知结果标记 | `controller.ts` 将 interrupted 纳入不确定性和证据不完整判定。业务写入后杀死 worker、脚本完成已记录步骤后退出，回归路径保留已完成步骤并持久化标记；应用关闭导致 Playwright 操作步骤先标为 failed 时，仍识别 application_exited 并保留未知结果标记。 |
| 进程清理失败长期持锁 | 清理失败的 Promise 可重新创建；定时器、显式会话关闭和整个 Controller 关闭都可重试；stdio 关闭失败继续保留最终退出期限。进程终止得到确认后才释放锁；释放失败保留待释放项。故障注入验证临时 EPERM 期间持锁、恢复后重试与后续账户使用。 |
| Unix 快速脱离后代 | 按审查建议明确轮询保证范围及 supervisor/容器要求。新 Unix 测试覆盖快速重归父进程后的原进程组清理，以及脱离进程组后由专用 supervisor 清理。轮询仍不是完整进程包含机制。 |
| 重复 URL 响应断言 | 根据前一动作开始时的请求序号与所选页面匹配响应；重定向沿用原始请求序号；验证旧 200 后新 500、延迟旧请求、旧请求重定向、其他页面响应和同一动作的重复断言。 |
| 截图单步超时 | 将显式超时传入页面、元素及隐藏 Electron 截图；自动失败截图继续使用默认值。 |
| UI 验收触发范围 | 两个触发器覆盖 UI 源码、构建脚本、包清单和 Go 依赖变更。 |
| 来源限制 | 保持仅导航的配置契约。复验发现原路由遗漏 HTTP 重定向；新增 Chromium 文档请求监督覆盖每一跳、初始弹窗和跨站 iframe。验证跨域 fetch、同源重定向及 POST 307 的正常行为，请求按浏览器语义发送一次。Service Worker 在测试上下文中禁用。Linux CI 捕获 Chromium 调试端口文件尚未落盘的启动竞争，已加入有界就绪等待，覆盖缺失、分段写入、CRLF、超时及进程已退出。Windows Gateway 联调又捕获端口文件读取失败；补充可能的 EACCES/EPERM/EBUSY 启动状态有界重试，持续拒绝仍返回 preflight_failed 并保留错误码。 |
| Raw trace 凭据 | `trace` 为管理员显式启用的原始敏感证据模式，现有契约已声明敏感数据风险；不承诺 ZIP 脱敏。本次验证默认账户会话不生成 trace，已知秘密从文本结果与默认工件中移除。 |
| 资源锁发布竞争 | 对所报告交错不改锁算法。新增双进程 barrier，暂停在 claim 发布前，验证先持锁者存在时后发布者被拒绝；保留原四进程互斥与计数测试。锁目录应位于具有一致原子文件操作的本地文件系统。 |
| MCP SDK 高危公告 | 锁定 `@modelcontextprotocol/sdk` 1.32.1；`npm audit --audit-level=moderate` 返回零漏洞，stdio 协议回归通过。公告：GHSA-6qxp-vccf-f47h；该公告涉及 SDK OAuth 客户端路径。 |
